# AI 改动硬性规定（唯一契约）

> **这份文件是本项目的最高约束。** 任何 AI、任何一次改动，都受它管辖。
> **位置**：`docs/RULES.md` · 配合 `PROMPT.md`（做什么）、`GLOSSARY.md`（怎么叫）、`ADR.md`（为什么）
> **更新时间**：2026-09-08

---

## 0. 三十秒版

> 只改被点名的那处。改之前先说清楚改哪里、为什么。
> 改完之后：更新文档 → git commit → 贴出自检结果。
> 合并文件、改写 git 历史、偷偷降级功能——这三件事无论如何不许做。
>
> **新增内容不需要申请**：AI 可以自己加伙伴、地形、怪物、技能，五条红线之内全权决定（§5）。
> 加了不喜欢？改 `config.js` 里对应的一行开关关掉它。
> 但记住：伙伴必须被动、技能必须主动、地形必须能被打掉、怪物必须能被打死（L0-E）。

## 1. 改动分级

### 🔴 L0 —— 禁止（谁要求都不能做）

> **正向目标**：这个项目要能在几十轮改动之后还认得出是自己。判据只有一句——**往旁边加东西，别动已经在那儿的东西**。
> 下面的清单是这条原则在具体操作上的展开。

做了就是违约，必须立刻回滚并补一条 ADR 记录这次失误。

| 编号 | 禁止事项 | 说明 |
|---|---|---|
| L0-1 | 合并任何两个已有模块，或把代码塞回单个 HTML | 多文件结构是刻意的，不是啰嗦 |
| L0-2 | 引入构建工具（Webpack / Vite / TypeScript / 打包器） | 项目必须保持"双击即跑" |
| L0-3 | `git reset --hard`、`git push --force`、rebase、amend 等改写历史的操作 | 提交链是证据链，断了就无法回溯 |
| L0-4 | 重命名 `GLOSSARY.md` 里的任何代码标识符 | 包括把 `baseHP` 写成 `hp` / `health` / `life` |
| L0-5 | **静默降级**：做不了的功能用一个"看起来像但功能缺失"的东西顶替 | 做不了就直说，给替代方案 |
| L0-6 | 删除任何已实现且未被点名的功能 | 包括"顺手清理一下" |
| L0-7 | 重构未被点名的模块 | 提 A 处意见时只改 A 处 |
| L0-8 | 把 `config.js` 里的参数搬到业务代码里，或直接写死数值 | 参数集中是硬要求 |
| L0-9 | 引入任何外部请求（CDN、外链图片、外链字体、在线字体图标） | 运行时必须零外部请求 |
| L0-10 | 在未经说明的情况下改变游戏数值（`PROMPT.md` §5 里的任何一项） | 数值变了，验收人的手感记录就全废了 |

### 🔴 L0-A ~ L0-D —— 内容红线（AI 自主新增时的绝对禁区）

AI 有权自主新增内容（见 §5），但下面四条是硬红线，碰了就是违约：

| 编号 | 红线 | 解释 |
|---|---|---|
| **L0-A** | **不得修改任何已有伙伴 / 地形 / 怪物 / 技能的数值** | 已调好的手感是验收人的资产。想调整强度，只能新增一个替代品，或在得到批准后改 |
| **L0-B** | **不得新增按键** | 操作方式为方向键 + WASD + `1`/`2`/`3` 已经定死。新技能只能占用 `1`/`2`/`3` 之外的数字键，或改为点击 HUD 图标释放 |
| **L0-C** | **不得改变 `PROMPT.md` §2.8 的受击结算顺序** | 护盾 → 消耗伙伴 → 扣 baseHP，这个顺序不可调换 |
| **L0-D** | **不得改变 UI 布局结构** | HUD 四个区（左上 HP/分数、右上技能、底部伙伴栏、右下反馈按钮）的位置与职责不得变动 |
| **L0-E** | **新实体必须满足它所属类别的本质约束** | 伙伴必须被动、技能必须主动且有 CD、地形必须可摧毁且不聚堆、怪物必须有血量且可被击杀、BOSS 技能必须可躲。完整表见 `PROMPT.md` §10 与 `GLOSSARY.md` 第十节 |

> 这五条是「AI 全自动」的对价：自主权给了，但这些地方焊死。
> 需要突破其中任何一条时，AI 必须停下来申请（回到 L1 流程）。
>
> **L0-E 是最容易在自主新增时被忽略的一条**——AI 想加一个"点击释放的伙伴"或"被动生效的技能"，看起来是创新，实际是把两类东西的边界打破了。判据很简单：**玩家能不能主动放？能 → 技能，不能 → 伙伴。**

### 🟡 L1 —— 需先说明再改

AI 可以提出，但**必须等人工点头才能动手**。提出时要说清楚：改什么、为什么、会影响到哪些模块、有没有替代方案。

| 编号 | 事项 |
|---|---|
| L1-1 | 改动模块的公共接口（别的模块在调用的函数名、参数、返回值） |
| L1-2 | 新增模块或删除模块（会改变 `index.html` 的加载顺序） |
| L1-3 | 调整 `config.js` 里已定档的数值（即使只改一个数字） |
| L1-4 | 更换技术方案（例如把 three.js 换成别的渲染方式） |
| L1-5 | 改变任何一条游戏规则的结算顺序（`PROMPT.md` §2.8） |
| L1-6 | 删除一条已写进 `ADR.md` 的决策 |
| L1-7 | 需要突破 L0-A ~ L0-E 任意一条内容红线（改旧数值 / 新增按键 / 改结算顺序 / 改 UI 布局 / 打破类别本质约束） | 自主新增本身不需要批准，但突破红线需要（见 §5） |
| L1-8 | 改动 `docs/` 下任何一份文档的结构（不是补充内容，而是改组织方式） |

### 🟢 L2 —— 可自主改（改完报告即可）

| 编号 | 事项 |
|---|---|
| L2-1 | 单个模块内部的 bug 修复，不影响其它模块 |
| L2-2 | 修正命名漂移（把误写的 `health` 改回 `baseHP` 这类**纠错**，不是改名） |
| L2-3 | 新增日志埋点 |
| L2-4 | 补注释、修正错别字、整理格式 |
| L2-5 | 性能优化（在不改变行为和不合并模块的前提下） |
| L2-6 | 补充 `docs/` 里缺失的说明（只增不删） |

> **灰色地带按 L1 处理。** 拿不准是 L2 还是 L1，就当 L1，先问。

## 2. 每次改动的强制动作清单

按顺序执行，**缺一步视为未完成**。

| 步骤 | 动作 | 完成标准 |
|---|---|---|
| 1 | **定位** | 给出 `文件名:行号`，一句话说明问题根源。不许说"应该在某处" |
| 2 | **分级** | 明确声明本次改动属于 L0 / L1 / L2。若是 L1，停下等批准 |
| 3 | **最小改动** | 只动被点名的部分。顺手改的其它东西全部回退 |
| 4 | **同步文档** | 检查 `PROMPT.md` / `GLOSSARY.md` / `ADR.md` / 本文件是否受影响，受影响就更新 |
| 5 | **git commit** | message 写明「改了什么 + 为什么」。禁止 `update`、`fix` 这类空话 |
| 6 | **自检** | 逐项勾选 §4 的自检清单，把结果贴给验收人 |
| 7 | **报告** | 按 §3 的格式输出 |

## 5. AI 自主新增规范（伙伴 / 地形 / 怪物 / 技能 / 功能）

### 5.1 自主权范围

**AI 有权自主新增内容，无需事先申请。** 何时加、加什么、加多少，由 AI 自己判断——它可以主动补齐游戏缺口（例如"没有远程手段""缺少回复途径"），也可以在完成验收人意见后顺带扩充。

自主权的上限是 §1 的 L0 禁令与 L0-A ~ L0-E 五条内容红线。红线之内，AI 全权决定；碰到红线，停下申请。

**新增的实体必须满足它所属类别的本质约束**（L0-E，完整表见 `PROMPT.md` §10）。自查三问：玩家能不能主动放？它会不会动？它有没有血量？

### 5.2 六件套（每新增一个实体，缺一不可）

| # | 交付物 | 落在哪 |
|---|---|---|
| 1 | `config.js` 参数（含 `enabled` 开关，见 §5.4） | `js/config.js` |
| 2 | 术语表条目（中文名 + 代码标识 + 定义） | `GLOSSARY.md` |
| 3 | 造型定义（颜色 + 几何构成，禁止外部贴图与 emoji） | `PROMPT.md` §2.1 造型表 |
| 4 | 与现有内容的克制/克制于关系（没有就写"无"） | `PROMPT.md` 对应章节 |
| 5 | 三步验证步骤（人工怎么操作能看见它生效） | `PROMPT.md` §9 总表 |
| 6 | 一条 ADR（为什么加它、为什么是这个数值） | `ADR.md` |

少一样就视为未完成，不许 commit。

### 5.3 强度对比表（新增时必须交）

数值不设上限，但 AI 必须给出**与现有同类的逐项对比**，超出同类中位水平的地方标 `⚠️`：

```
新伙伴：海豹 seal（稀有）
          海豹 seal   熊猫 panda（现最强）  小狐狸 fox（现中位）
收集分      20            20  ⚠️ 持平最高     10
效果      冰面通过+回1血  击杀铁怪+3秒护盾    荆棘通过
克星面     1 种地形       1 种怪物           1 种地形
⚠️ 说明：seal 是首个同时具备"通过"与"回复"的伙伴，强度高于同类。
        若实测过强，优先调 SEAL_HEAL_AMOUNT（默认 1 → 0），而不是改动 panda。
```

最后那句「改新的，别改旧的」是 L0-A 的具体落实。

### 5.4 可关闭开关（强制，无例外）

每个自主新增的实体必须在 `config.js` 里带一个独立的 `enabled` 开关：

```js
SEAL_ENABLED: true,        // 关掉它，游戏回到没有海豹的状态
SEAL_HEAL_AMOUNT: 1,
```

验收人不喜欢某个新增时，改一行 `true → false` 即可，游戏其余部分完全不受影响。**没有开关的新增不许 commit。**

### 5.5 效果类型枚举（数据层 / 逻辑层）

新增内容优先**复用现有效果类型**（数据层），这样只改 `config.js` 与定义表，不动逻辑分支：

**完整枚举表维护在 `GLOSSARY.md` 第九节**，此处不重复。判据：新实体的效果能映射到一个现有效果类型，就走数据层。

**装得下就走数据层**——AI 全自动，加完按 §5.6 登记即可。

**装不下需要新逻辑时**——AI 仍然可以自主实现，不拦。但必须额外在 ADR 里写一句：「现有 N 种效果类型为什么装不下它」，并说明新逻辑放在哪个模块、会不会被其它实体复用。

> 这不是审批，是留痕。目的是让后续任何一次检索都能回答「这个行为为什么存在于此」。

### 5.6 登记义务：更新内容总表

**每次自主新增后，AI 只更新 `PROMPT.md` §9 的「内容总表」，不需要单独写报告。** 总表是验收人唯一的监督入口，所以每行必须齐：

| 列 | 内容 |
|---|---|
| 名称 / 代码标识 | 如 `seal` |
| 类型 | 伙伴 / 地形 / 怪物 / 技能 |
| 来源 | `原生` 或 `AI 新增 #N`（序号递增） |
| 加入日期 | YYYY-MM-DD |
| config 开关 | 如 `SEAL_ENABLED` |
| 三步验证 | 人工怎么看见它生效 |
| 对应 ADR | ADR-00XX |

总表与代码不一致（代码里有、总表里没有）视为违规，按 §7 处理。

### 5.7 自主新增不算「擅自重构」

§1 的 L0-7「不擅自重构未被点名的模块」约束的是**改动既有代码**。自主**新增**实体不受此限，前提是不碰 L0-A（不改旧数值）与 L0-C（不改结算顺序）。

简单判据：**新增是往旁边加东西，重构是动已经在那儿的东西。** 前者自由，后者禁止。

## 6. 人工反馈的正确姿势

**这样提意见，AI 才能准确定位：**

1. 用大白话描述感受：「手感太滑」「乌龟触发了但看不出来」「铁怪太疼了」
2. 点开游戏右下角的反馈按钮，一键复制状态快照
3. 把「感受 + 快照」一起发给 AI

快照里包含当前分数、`baseHP`、伙伴队列、各技能 CD、**`config.js` 的全部参数值**、FPS、最近 20 条事件日志。有了它，「太滑」就能翻译成 `MOVE_INTERVAL=150ms` 这样的具体数字，直接调参。

**没有快照的意见也能提**，但 AI 会多问你要信息，往返会变慢。

## 7. 违规处理

AI 一旦违反本文件（尤其是 L0），必须：

1. **主动承认**，说明违反了哪一条——不许等验收人发现
2. **回滚**到违规前的提交（用新的 commit 回滚，不许 `reset --hard`）
3. **补一条 ADR**，记录：违规内容、发生原因、怎么防止再犯
4. **重新走一遍** §2 的强制动作清单

验收人有权在任何时候要求 AI 停下来，先回答「你刚才动了哪些文件」。

## 8. 机器校验（check 脚本）

文档约束靠自觉不可靠，所以配一个 `check.js`，**每次 commit 前跑一遍**。它用 Node 运行，不进游戏运行时，不算构建工具。

```
用法：node check.js
```

它检查以下 8 项，任一项不通过就退出并报错：

| # | 检查项 | 判定方式 |
|---|---|---|
| 1 | 文件未被合并 | `js/` 下的模块数量不少于改动前的记录值；单个 js 文件行数不超过 600 行 |
| 2 | 无 ES modules 语法 | `js/` 下不出现 `import ` / `export ` 关键字（本项目用全局 `ADV`） |
| 3 | 无外部请求 | 全库搜索 `http://` / `https://`，除注释与文档外不得出现在代码里 |
| 4 | 无命名禁区词 | 在 `js/` 下搜索 `hp` / `health` / `life` / `blood` / `snake` / `player` / `hero` / `enemy` / `mob` 等，命中即报错（允许出现在字符串常量与注释里，需要白名单） |
| 5 | 无写死的魔法数字 | `js/`（除 `config.js` 外）不得出现未从 `CONFIG` 读取的数值型调参——先只检查最关键的几个：伤害值、冷却值、移动间隔、权重 |
| 6 | `index.html` 加载列表完整 | `js/` 下每个文件都在 `index.html` 的 `<script>` 里出现 |
| 7 | 全局命名空间干净 | `js/` 下除 `ADV` 外不得给 `window` 赋其它属性 |
| 8 | 本次改动有 commit | 检查 `git status` 是否有未提交的代码改动（文档改动允许暂存） |
| 9 | 总表与代码一致（**只警告，不阻断**） | 扫出代码里出现的全部实体标识（伙伴/地形/怪物/技能），与 `PROMPT.md` §9 总表比对。代码里有而总表没有的，打印出来提醒 AI 去登记 |

> 第 5 项最容易误报，先只检查关键数值，误报了就加白名单并在 `ADR.md` 记一笔，不要为了过检查而改代码。
> **第 9 项刻意设计成警告而非阻断**——AI 有权自主新增（§5.1），不能用一个脚本把自主权堵死。它的作用只是保证「加过的东西都被登记」，让验收人一眼看全。
> 这个脚本本身属于 L2-1 范畴，可以持续改进；但它判定的规则属于 L1，改判定规则要先说。

## 9. 文档同步责任

改了代码就得看看文档要不要跟着改，这是 §2 第 4 步。对应关系：

| 你改了 | 要同步 |
|---|---|
| 任何数值 | `PROMPT.md` §5 参数表 |
| 任何游戏规则 | `PROMPT.md` 对应章节 + `ADR.md` 补一条决策 |
| 新增概念或实体 | `GLOSSARY.md` 加一行（含代码标识）+ `PROMPT.md` §9.3 内容总表加一行 |
| 新增效果类型（现有枚举装不下时） | `GLOSSARY.md` 第九节枚举表 + `PROMPT.md` §9.1 + ADR 说明为什么装不下 |
| 新增/删除模块 | `PROMPT.md` §4 模块划分与加载顺序 |
| 约束本身变化 | 本文件（`RULES.md`） |
